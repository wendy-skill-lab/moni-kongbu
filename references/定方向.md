# 第一步：定方向（最恐怖的点 + 场景）

## 先定一个画面，其余都从它长出来

先和用户讨论，定下**最恐怖的画面或声音**，以及**用什么设备、怎么让观众看到它**。之后再展开剧情、台词和界面。

剧情可以不完整，这类片子靠的是戛然而止；但**视觉呈现必须有逻辑**：每一个画面从哪来、为什么主角会看到、看到的东西在空间里在哪，都要说得通。

| | 《宝宝一直在笑》 | 《已就寝》 |
| --- | --- | --- |
| 现实处境 | 妈妈出差，家里只剩老公和 8 个月的女儿，她只能靠看护器远程看娃 | 中式军事化管理的高中：看班监控、AI 抬头率，家长在手机上盯着孩子上晚自习 |
| 最恐怖的那个画面 | 爸爸背对镜头、脸贴着墙站在婴儿房墙角，一动不动，身上的识别圈写着“爸爸”，已经站了 4 小时 32 分 | 熄灯的教室里，全班 46 个人坐得笔直、双手叠放、目视正前方，一起张嘴背书；每张脸上一个绿框“抬头 0.9x”，抬头率 100% |
| 用什么设备呈现 | 婴儿看护器的夜视实时画面 + AI 识别圈 | 家校看班小程序的教室监控 + AI 检测框和人数统计 |
| 怎么被发现 | 云台向左转，转过关着的门，转到平时拍不到的墙角，观众和她同一秒看到 | 未就寝推送 → 在群里问老师 → 老师说早回去了 → 她自己打开监控 |
| 主空间 / 辅助空间 | 婴儿房 / 她住的酒店（只在她的手机里） | 高一(7)班教室 / 宿舍（只在推送和老师的话里） |

两条的共同点**不在画面内容，而在做法**：先有一个现实处境，找到这个处境里天然存在的设备，再让这台设备记录下一件和人话对不上的事，最后用一个冷静的系统字段把它量化。设备要和处境天然绑在一起：出差就有看护器，住校就有看班监控，代驾回家就有车企 App。

**“熟人站在墙角、背对镜头”不是公式。** 恐怖也可以来自痕迹、声音、文字、数据、位置、规则、群体、动物反应、视角和时间。先挑表达方式，再挑设备。

## 五条底层原则（不限形式，每期都守）

1. **恐怖的源头不给全貌。** 只给痕迹、读数、轨迹、声音或模糊的轮廓，不给清楚的五官和全身。
2. **观众要拿到证据。** 每期提供一段非聊天的设备画面、照片、录音、记录或地图。
3. **揭示靠“动起来”或者“对照”。** 设备动起来：云台转动、捏合放大、回放逐帧、相册往上翻、机器人开过去、长按实况照片。或者拿平时做对照：平时相似度 98%，今晚 63%。观众和主角在同一秒发现。
4. **两个信息对不上。** 人说的话和记录里的事实对不上：老师说“已经回去了”，监控里他还在；妈妈说在高铁上，门锁说妈妈刚开了门。观众自己会问：那一直在跟我说话的是谁？
5. **结尾戛然而止，或者把时间往前推。** 线索在开头就埋好。不写“我也被附身了”。

**每期更换主表达。** 一期 = 1 个主表达 + 1–2 个辅助；根据自己的选题记录避免重复。

## 场景怎么定

- **诡异只发生在一个空间里**：卧室、婴儿房、教室、车内、民宿次卧。其他空间只作辅助：主角所在的地方，或者对话里提到的地方。
- **场景和恐怖点同时定。** 先问“最吓人的那个画面发生在哪”，空间就定了；空间一定，“什么设备会天天拍着这个空间”也就定了。
- **空间里的方位提前定死**：机位在哪、门窗在哪、墙角在哪、主角的座位或床在哪。之后每一个画面都要守住这个方位。比如《已就寝》里陈默坐最后一排靠窗，后墙角在机位斜对面，老师就必须走到最后一排去叫他。
- **单夜实时。** 只写一个晚上，时间连续推进（21:14 → 22:12 → 22:17）。不要出现“第二天”“三天后”。
- **设定要具体。** 高中就写“高一(7)班”、校服、晚自习 19:00–21:40、宿管；群名带人数，比如“高一(7)班家长群(96)”。

## 画面形式（不限于摄像头）

只要模型能生成出像真机拍的画面就行：家用监控、婴儿看护器、学校看班、车内摄像头、行车记录仪、门铃和猫眼、送达照片、扫地机器人的避障照片、野外红外相机、热成像、无人机航拍、地图街景、手机照片（夜景、人像、实况、连拍、延时）、视频通话、直播回放、录像带。要求只有两条：**观众能亲眼看到画面**，并且这个设备在这个处境里是自然存在的。

画面里不一定要有人。画面可以和数据对不上、可以少了什么、可以只留下痕迹，也可以正常画面配上不对的声音。声音、数据、文字记录同样能当“直给的证据”，完整清单见 `恐怖怎么表达.md` 的“载体不限”。

## 选题会火的条件

- **建立可分享的现实处境**：伴侣、家长、室友、独居、出差、带娃或住校。
- **有现实情绪更好**：《已就寝》踩中的是家长对学生的监视，这种“监视”本身就让人不舒服，恐怖只是把它推到极端。
- **三类结构**：A 聊天主线穿插设备；B 开头就给异常；C 全程单一监测器界面。

## 方向卡片（给用户挑的格式）

一次出 3–4 个方向，最后明确推荐一个。每个方向写：

```
### 方向 N：《片名》　A/B/C 类
- 最恐怖的点：一个画面或一个声音。写清楚观众具体看到、听到了什么，在空间的哪里，画面上的系统字段原文是什么。
- 主表达 / 辅助：第 N 种 + 第 N 种（编号见 恐怖怎么表达.md）。
- 怎么用视觉呈现：哪种设备、什么机位、怎么“动起来”被发现。
- 场景：主空间 + 辅助空间 + 时间（几点到几点，单夜）。
- 现实处境：观众为什么会代入、会转发给谁。
- 一句话钩子：能放在标题“｜”后面的一句话。
- 人物：主角“我”是谁，在跟谁聊天（微信备注、关系）。
- 粗节拍：5–7 行，从轻松开场写到戛然而止。
- 矛盾点：我发现了什么不对劲、怎么质问、诡异怎么发生。
- 结尾：停在哪个事实上。
- 封面画面：那个最能截图、最能玩梗的画面。
```

一批方向放在一起时要满足：主表达各不相同；至少一个方向的主表达不是“画面里的人”；把各方向的“最恐怖的点”并排放，换个设备就能互换的，说明只是换了一层皮，要重想。

片名 2–5 个字，像一句话或一个系统字段：已就寝、宝宝一直在笑、我们到了、说话人3。

## 和用户讨论的方式

- 先定场景，再收窄设备与恐怖点；每一版另存文件，不覆盖旧版。
- 用户给出自己的开头或修改时，**保留用户的原话和设定**，只补空缺的部分，并说明补的逻辑。
- 用户问“到底看到了什么”时，要讲清楚每一帧画面上具体有什么，不要讲抽象的寓意。
- 结尾拿不准时，一次给 3–4 个结尾方向，每个都写成“最后一个画面 + 最后一个声音”。
- **用户说“做吧”“生成吧”之前，不写正式脚本，也不做素材。**

## 常见叙事错误

避免开场就泄露核心异常、跨天跳叙、让系统无由头地替角色收尾、只聊天没有证据，以及每期只换设备不换恐怖点。角色自然出现，线索可回看，结尾停在已经铺垫的事实上。
