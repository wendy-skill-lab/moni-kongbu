# 实拍质感：监控、看护器、录像、照片要和真机拍的分不出来

设备实拍质感来自光线、机位、码流缺陷与界面的一致性。每张非聊天素材按本规范制作并按第 8 节审片。

## 1. 判断标准

只有一条：**截一帧，和同类设备的真实截图并排放，分不出哪张是生成的。** 光“看起来挺清楚、挺好看”不算数，好看本身往往就是破绽。

每期开工前，先给这期要用的每种设备找 2–3 张真实截图当参照，存进 `research/real_refs/`。用 search 的 image 类型去搜，比如“商场 夜间 监控画面 截图”“家用摄像头 夜视 截图”“看护器 夜视 画面”“行车记录仪 夜间 截图”“猫眼 门铃 画面”。安防厂商的“夜视效果不好常见问题”这类售后页面最好用：配图都是真机原图，不加修饰。母版出来以后，和参照图并排看一遍（第 8 节）。

## 2. 虚构范例的设备质感

| 画面 | 像真的地方 |
| --- | --- |
| 《已就寝》白天教室（S1） | 机位装在教室前方侧墙，偏低偏侧，是装修师傅装的位置，不是给剧情找的角度；2.8mm 广角，右侧窗框明显向外弯；日光灯管全部过曝成白条，约 3% 的像素是纯白；校服、书摞、窗帘、公告栏这些杂物很多；暗部有噪点 |
| 《已就寝》熄灯（N1）和全班（W） | 熄灯后自动切成黑白红外；离镜头近的桌面和书被红外灯打白；远处发灰；人坐着不动，只有头轻微浮动 |
| 《宝宝一直在笑》婴儿房 | 天花板角落俯拍，轻微鱼眼，四角暗；灰色红外，发雾，暗部发糊；引擎再叠一层逐帧跳动的噪点；画面放在看护器 App 的小窗里，上有设备名和码率，下有功能按钮 |
| 两条共同 | 时间水印、检测框、人数都由界面层画，格式照真产品；画面平淡日常，恐怖只在一处；镜头锁死，人动作慢、幅度小 |

## 3. 常见反例

夜间照明均匀、没有高光过曝、没有暗部噪点和压缩、边缘直线完全笔直、主体居中且像摆拍，都会让设备画面显得像渲染图。按同类真实设备截图校正，不以“好看”作为验收标准。

## 4. 九条要素（生成提示词和审片都按这九条）

| 要素 | 规则 | 模型最常犯的错 |
| --- | --- | --- |
| 1. 光线合时间 | 先想清楚“这个钟点，这个地方，哪几盏灯还亮着”，写进提示词。室内开着灯就是彩色；熄灯、深夜、无人的地方，摄像头会自动切成黑白红外 | 深夜的场景亮得像白天；关了灯还是彩色；光打得很均匀 |
| 2. 机位是装出来的 | 家用和看护器装在天花板角落或柜顶，高角度俯拍；店铺、教室、楼道装在墙角或吸顶，2.5–3 米高，斜着拍；门铃在门上齐胸高；行车记录仪在后视镜后面。构图服从“要拍到门、收银台、全班”，不服从剧情 | 平视、居中、对称，像电影机位 |
| 3. 镜头是广角 | 2.8mm 左右，边缘直线外弯，四角暗；门铃和猫眼是强鱼眼 | 直线全是直的，没有暗角 |
| 4. 曝光窄 | 灯、窗、屏幕、反光地面过曝成白块，带一圈光晕；暗部压黑、有噪点；红外下离镜头近的东西被打白，远处很快变黑 | 高光有细节、暗部也有细节，像 HDR |
| 5. 颜色淡 | 彩色监控饱和度低，有偏色（日光灯偏绿，暖灯偏黄）；红外是中性灰，发雾（黑位抬高）；看护器的红外略偏绿 | 颜色鲜艳、通透；红外做成夜视仪那种绿色 |
| 6. 画质是码流 | 400 万像素的摄像头，在手机 App 里看的是“标清”或“高清”码流：细节被降噪抹平，噪点一团一团，暗部和渐变有压缩块，边缘有锐化白边和细微紫边 | 每根头发都清楚，或者像加了胶片颗粒 |
| 7. 时间水印照真产品 | 监控左上“2026-11-12 星期四 23:18:06”，粗体白字黑边，每秒跳一下，卡顿时停住；机位名在右下（“高一(7)班”“橱窗内侧”“客厅”）。家用和看护器 App 通常只在画面左上有小号时间。一律由界面层画，或用 `cctv_look.py --osd` 烧录，不让模型画 | 模型画出歪字；没有星期；字体太细、太好看 |
| 8. 内容平淡、杂 | 真地方到处是杂物：纸箱、拖把、线、插座、灭火器、安全出口灯、贴歪的通知。人做最普通的事，不看镜头，在画面里很小、偏在一边 | 干净得像样板间；主角正对镜头、光正好 |
| 9. 动作和时间 | 镜头完全不动；人动作慢；走动的人有拖影；视频 15–20 fps，偶尔卡一帧；每隔一两秒画质“呼吸”一下（关键帧） | 镜头缓慢推进或漂移；动作顺滑得像电影；24 fps 的电影感 |

## 5. 各设备画质卡

写脚本时，每个【实拍】段都按下表写一行“画质”。做后期时用对应的 `cctv_look.py` 预设。

| 设备 | 机位和镜头 | 彩色还是红外 | 画质 | 水印和界面 | 预设 |
| --- | --- | --- | --- | --- | --- |
| 家用云台摄像头（客厅、卧室） | 柜顶或天花板角落，俯拍，广角明显；云台能转 | 开灯彩色，关灯黑白红外，中心亮四周暗 | 标清码流，糊，噪点重 | App 里左上小号时间；上方设备名和码率“14 KB/S”，下方对讲、截图、录像、云台 | `homecam` / `homecam_ir` |
| 婴儿看护器 | 婴儿床上方或天花板角落，高角度俯拍，轻微鱼眼 | 夜里几乎全是红外，略偏绿灰 | 比家用更糊、更暗，四角很暗 | 哭声提醒、宝宝醒来、人形检测这类事件卡片 | `babycam_ir` |
| 学校看班、店铺、商场、楼道（海康、大华这类） | 墙角或吸顶 2.5–3 米，斜着俯拍，2.8–4mm 广角 | 开灯彩色；熄灯切红外 | 高清但压缩明显，灯管过曝 | 左上“日期 星期 时间”，右下机位名；学校看班平铺家长水印 | `cctv_color` / `cctv_ir`（关灯后硬撑彩色加 `--night`） |
| 电梯 | 轿厢顶角，强俯拍，鱼眼 | 彩色，日光灯偏绿 | 低码率，人走动拖影 | 左上时间，有时有楼层数字 | `doorbell` 或 `cctv_color` 加大畸变 |
| 门铃、猫眼 | 门上齐胸高，强鱼眼，走廊两头弯成弧 | 楼道灯亮时彩色，灭了就红外，人走近脸会过曝 | 码流低，动起来会糊 | 有人按铃、有人停留的推送带抓拍图 | `doorbell` |
| 行车记录仪 | 后视镜后面，超广角，引擎盖在画面底部 | 彩色；夜里路灯和车灯过曝拖尾 | 锐、反差大，暗部糊 | 底部日期时间、车速、GPS | `dashcam` |
| 野外红外相机 | 树干或墙上齐腰高 | 夜里红外闪光：近处过曝，远处全黑 | 动的东西拖影，连拍三张 | 底部一条信息栏：日期时间、温度、月相 | `trailcam` |
| 手机夜景照片 | 手持，随手构图，轻微歪 | 彩色，算法把暗部提亮 | 暗部涂抹、灯有光晕、锐化重 | 相册详情里有时间、地点、机型 | `phone_night` |
| 视频通话、直播 | 前置摄像头，脸近 | 彩色 | 网络差时马赛克、冻结、音画不同步 | 通话计时、信号弱提示 | 不用预设，按 `真实感.md` 做卡顿 |

热成像、录音波形、地图轨迹、门锁记录这类“不是画面”的记录，见 `真实感.md` 第 7 节的表。

## 6. 生成提示词怎么写

generate_image 和 generate_video 要求英文提示词。下面按中文列要点，写的时候翻成英文；画面里如果要出现中文字，照原样保留。九条要素逐条落到提示词里：

| 必须写进去 | 写法示例 |
| --- | --- |
| 这是什么设备的什么画面 | “一台便宜的吸顶半球监控在 23:18 拍到的原始画面，像店主在手机上截的图；不是照片，不是电影” |
| 机位、高度、镜头 | “装在店里天花板角落，约 2.8 米高，2.8mm 广角，约 35 度俯拍橱窗；桶形畸变明显，左边的衣架和窗框向外弯；四角轻微暗角；构图是安装师傅定的，不为剧情构图” |
| 此刻亮着哪些灯 | “店里顶灯全关，只有橱窗上方两盏射灯亮着，模特肩膀过曝成纯白；走廊大部分是暗的，卷帘门拉下，每隔三盏亮一盏值班灯，每盏都是带光晕的白点；远处一盏绿色安全出口灯” |
| 人在哪、多大、在做什么 | “偏右、半个身子在暗处，低头看手机，手机屏照亮下巴和手；在画面里很小，看不清脸” |
| 杂物 | “左边一排挂满衣服的衣架、地上一个纸箱、价签架、靠墙的拖把、地上用胶带贴着的线” |
| 码流画质 | “400 万像素的监控，但在手机 App 里看的是标清：细节被降噪抹平，暗部有一团团的亮度和彩色噪点，暗部和渐变有块状压缩，亮边有细微紫边，边缘锐化过度有细白边，饱和度低，混合光偏黄绿” |
| 红外时额外写 | “所有灯都关了，摄像头自动切到黑白红外：灰、对比低、黑位发雾；红外灯照亮近处后很快衰减，最近的东西过曝发白，四角暗；大玻璃会把红外反射回来，形成一片发白的雾，玻璃外几乎看不见；不要绿色夜视” |
| 避免 | “电影光、HDR、均匀布光、光滑的 3D 渲染感、景深虚化、对称构图、主角正中、镜面一样干净的地面、任何文字、时间戳、标志、水印、店招文字” |

通用母版提示词和虚构范例见 `提示词.md` 的 P6。

**两个模型各出几张，挑最平淡、最“不好看”的那张。** 漂亮、通透、构图讲究的候选直接淘汰。

## 7. 后期：`scripts/cctv_look.py`

模型出来的图再怎么写提示词，还是偏干净，所以**每一张实拍静帧和每一段实拍视频都要过一遍后期**，而且同一机位的母版、变体、视频用同一个预设和同一组参数，前后切换才不会跳。

```bash
S=<技能目录>/scripts/cctv_look.py
python3 $S assets/gen/母版.png --report                                   # 先体检：太干净？高光没过曝？太鲜？
python3 $S assets/gen/母版.png assets/stills/S1.jpg --preset cctv_color --no-distort --width 1920
python3 $S assets/gen/熄灯.png assets/stills/N1.jpg --preset cctv_ir --no-distort --width 1920
python3 -u $S assets/video/clip.mp4 assets/video/clip_look.mp4 --preset cctv_ir --no-distort --fps 15 --stutter 0.02 < /dev/null
ffmpeg -i assets/video/clip_look.mp4 -r 24 -vf scale=1280:720 -q:v 3 assets/frames/<名>/f%03d.jpg   # 引擎按 24 fps 读帧，15 fps 的顿挫会保留下来
```

它按顺序做：广角畸变和暗角，红外去色和中心亮斑，曝光增益和高光过曝加光晕，黑位抬升，降饱和和偏色；然后降到码流分辨率，镜头发软，ISP 锐化，补噪点（粗细两层、暗部更重），在码流分辨率下压缩，再放大回输出尺寸。视频逐帧重新出噪点，降到 15 fps，偶尔卡一帧，按低码率和关键帧间隔重编码。

| 参数 | 什么时候用 |
| --- | --- |
| `--no-distort` | 模型出的图已经有广角畸变了（按第 6 节写提示词，通常都有）。不加会弯两次 |
| `--night` | 彩色预设，但场景很暗、摄像头硬撑着没切红外：增益拉高，噪点更重，颜色发灰 |
| `--set noise_l=4` 等 | 微调任一参数；`--list` 看全部预设 |
| `--osd` / `--channel` | 只在需要把水印烧进画面时用（整屏回放、封面、单独发给用户看的样图）。片子里的监控照旧由界面层画水印，不要画两遍 |
| `--report` | 画质体检：量平坦区噪点、暗部噪点、饱和度、过曝比例、压缩块，给出“太干净”“高光没有过曝”“颜色太鲜”这类提示 |

噪点是“补差额”：先量原图在码流分辨率下已经有多少噪点，只补不够的部分。所以模型已经给了噪点的图不会被叠成雪花。

**引擎里的动态噪点层还要留着。** 静帧在片子里一放好几秒，烤进图里的噪点是不动的，不动的噪点一看就是一张图。看班模块的 `IRN()` 每帧换一张噪点叠在上面（红外透明度约 0.2，彩色约 0.07）。图过了 `cctv_look.py` 之后，把 `build_data.py` 里的 `NOISE_K` 从 1.0 改成 0.6，让这层只负责让画面“活着”，不再把噪点叠两遍。

## 8. 审片：三种看法都要过

| 看法 | 查什么 |
| --- | --- |
| 和真实截图并排（同尺寸） | 先遮住标签，问自己分不分得出哪张是生成的。分得出，就按第 4 节九条找出是哪一条露了馅 |
| 放大到 100% | 噪点是不是一团一团（不是均匀细砂）；有没有压缩块；人脸是不是糊到看不清五官；有没有模型画出来的歪字 |
| 放进手机界面，按实际显示大小看 | 过曝和暗角在小窗里还看不看得出；画面亮度和 App 界面的黑色协不协调；关键线索在小窗里是否还看得到（看不到就安排捏合放大） |

常见失败和处理：

| 现象 | 处理 |
| --- | --- |
| 体检报“太干净”“高光没有过曝” | 先查提示词有没有写亮着哪些灯、有没有写过曝；再过后期 |
| 夜里的场景是彩色而且很亮 | 回到第 4 节第 1 条，重写光线，或者改成红外版 |
| 红外版像电视雪花 | 噪点太重。真红外是发灰发雾，降低 `noise_l`，提高 `black` |
| 广角弯得太夸张 | 原图已有畸变，加 `--no-distort` |
| 母版和视频切换时“跳”一下 | 两边用的预设或参数不同；或者视频首帧不是母版本身 |
| 视频顺滑得像电影 | 用 `--fps 15 --stutter 0.02`；视频模型常把噪点抹掉，后期要重新加 |
| 视频镜头在慢慢推、慢慢漂 | 重新生成，提示词写“镜头完全固定”；还漂就换能守住机位的模型（`制作.md` 第 3 节） |
