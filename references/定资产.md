# 第五步：定资产（实拍画面逐段确认后才生成视频）

用户确认第四步脚本后，才建项目、调研界面和制作静帧。视频生成后换机位、构图、人物位置、人数或光线通常需要重做该段，因此先在静帧阶段确认大框架。不承诺固定耗时或生成成本；先说明受影响资产和可保留的段落。

**只向用户确认实拍画面。** 方位图、母版、视频首尾帧、关键画面和藏回看线索的照片决定视频长相，必须确认。聊天、锁屏推送、设备 App 界面帧及头像壁纸由 AI 对照脚本和参考笔记自检，不逐段询问。设备页可以放进板里当参照，确认的是其中的实拍画面，不是 UI。纯聊天段不出确认板。

## 1. 制作前的边界

先读 `资源说明.md` 和 `制作.md` 第 1 节，运行只读环境检查，核对本次制作授权、生成工具与人物/品牌边界。检查通过不等于拥有生成额度或第三方素材权利。按当前可用的 imagegen、image-processing 技能和工具说明执行；没有生成能力时交付资产需求、提示词和待生成清单，不能把占位图报成已完成。

真实产品截图用于研究布局和画质，记录来源，不默认放入成片。原创生成素材和用户提供素材都要记录来源与使用范围；虚构人物、群名、学校与设备字段不得让人误认为真实事件。

## 2. 锁定清单

| 要确认的 | 在哪张图上核对 |
| --- | --- |
| 主空间方位：机位、视野、门窗、家具、人物位置朝向 | 方位图 |
| 镜头、高度、构图 | 母版静帧 |
| 哪几盏灯亮着，彩色还是红外 | 母版及变体 |
| 人物人数、位置、姿势、衣着 | 变体 |
| 每段视频的首尾状态 | 对应首帧/尾帧 |
| 最恐怖的那一帧、第一遍与回看线索 | 关键静帧与照片 |
| App 页面、群名人数、备注、系统字段原文 | 界面 QA 帧，AI 自检 |
| 头像、壁纸 | 对应静帧，AI 自检 |
| 藏回看线索的聊天照片 | 照片原图，用户确认 |
| 同一时空、主角第一视角、文字主导 | 全部资产与确认脚本一起看 |

## 3. 顺序

1. **建项目与 PLAN。** 用 `scripts/new_film.sh`，按 `制作.md` 的当前环境说明操作。立刻写 `PLAN.md`：恐怖要素、第三步确认的标志画面、定稿脚本路径、资产表、技术规格和权利备注。不要覆盖非空项目。
2. **界面和设备调研。** P5 结果写 `research/ui_reference_notes.md`；每种设备找 2–3 张真实截图存 `research/real_refs/` 并记来源。调查功能现实依据，剧情扩展字段注明演绎。真机截图首次细看后写清版式、文字、颜色、字号与按钮位置；后续优先读笔记，缺信息才重看原图。
3. **方位图先确认。** 把脚本空间信息写入 `research/floorplan.json`，包含机位、视野、门窗、家具、每个人的位置和朝向。按脚本帮助和 `templates/floorplan_example.json` 配置，运行：

   ```bash
   python3 src/floorplan.py research/floorplan.json research/floorplan.png
   ```

   先给用户确认，再出静帧；改方位先改 JSON，不拖到视频阶段。
4. **母版决定机位与质感。** P6 生成母版，按当前工具可用模型做候选，不强制调用未开放的模型。挑平淡、日常、不像电影的图，过 `cctv_look.py` 后期，与真实参照并排审。单独给用户确认母版，保留未后期原图供编辑和视频输入。
5. **变体覆盖每段状态。** 用 P7 在未后期母版上编辑每段视频的首帧、尾帧和标志画面。机位与未改部分不变，同一光线条件使用同一后期参数。明确哪一帧是确认版本，不拿候选或旧版当输入。
6. **界面帧。** 将脚本写入 `src/build_data.py` 粗时间轴，实拍暂用确认静帧。构建时间轴和页面后，在项目 `src/` 中执行 `node render.js qa <时刻,...>`；每段出 1–3 帧，包含第一眼及关键消息/字段。AI 对照脚本和参考笔记自检群名、人数、备注、字段、时间和遮挡，记录自检结果；不发给用户确认。此处只作界面 QA，不做全片渲染。
7. **头像、壁纸、照片。** 用 P12 或有授权的素材；头像和壁纸 AI 自检，不发用户确认。藏回看线索的照片必须在本阶段实际做出，请用户确认“第一遍不抢眼、暂停能验证”。不生成或冒用真实人物身份。
8. **资产板。** 在项目根写 `asset_board.json`，参照 `templates/asset_board_example.json` 和工具帮助，运行：

   ```bash
   python3 src/asset_board.py asset_board.json
   ```

   输出 `qa/asset_board/board_*.jpg`。只给有实拍画面的段落做确认板，包含方位图、母版、视频首尾帧、关键帧或线索照片；聊天、头像、壁纸不放上板请求确认。写段号、时间、标题、状态和资产说明；缺失实拍资产显示“待生成”，不是确认完成。
9. **逐段确认。** 一次给一到三段，每段附“这段要确认的是……”：机位、人数、姿势、光线、首尾状态或照片线索。用户确认后更新资产板和 `PLAN.md`，需要改的先改图重拼。明确确认范围，不能将一句“继续”解释为缺失资产全部通过。

方位图和母版先发；之后按段给变体、关键帧和藏线索的照片。界面帧、头像和壁纸不发确认。不让用户自己在一堆图中猜要检查什么。

## 4. 项目资产表

以下是通用表格，不是私人项目记录：

```text
| 段 | 资产 | 文件 | 状态 | 确认点/待改项 | 来源与权利 |
| --- | --- | --- | --- | --- | --- |
| 全片 | 方位图 | research/floorplan.png | 待确认 | 机位、视野、人物朝向 | 本项目绘制 |
| 全片 | 母版 | assets/stills/M1.jpg | 待确认 | 构图、灯光、设备质感 | 本项目生成 |
| 段 2 | 视频首帧/尾帧 | assets/gen/V2_a.png / V2_b.png | 待确认 | A → B 的状态 | 本项目生成 |
| 段 1 | 推送界面帧 | qa/t_3.40.png | 自检通过 | 群名、字段、遮挡由 AI 核对，不发用户确认 | 本项目渲染 |
```

实拍状态分别记录待生成、待确认、要改、已确认；界面另记自检通过，不能替代实拍确认；资产板脚本的具体枚举以随附示例和帮助为准。文件不存在、缺少来源或确认点不清楚时，不得写成已确认。

## 5. 本阶段不做什么

不生成视频、不配人声、不混音、不渲染全片。声音需求可以列出，但试听放到第六步，避免用户同时判断视觉与声音。若资产调整影响剧情或方位，先改脚本另存并重新确认，再改资产。

**所有段落所需实拍资产都已由用户确认，界面 QA 自检通过后，才进第六步。** 视频的未后期首帧与后期预览须能互相对应；不得悄悄换机位、构图或人物。

## 6. 视频后要求改大框架

先说清需要回到本阶段的资产、重新生成的片段与可沿用的部分，取得确认后再做。换场景、机位、人物位置人数或恐怖要素会触发资产重新确认；若故事骨架也变，先回前面的方案或脚本关卡。仅改台词、字段、声音、节奏或同构图小动作时，按 `制作.md` 第 8 节局部修改并记录真实检查结果。
