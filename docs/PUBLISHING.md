# 公开仓库与 Skill 的发布约定

本仓库兼顾人和 Agent，但不把两种文档混成一份。README 说明它是什么、能做什么、不能做什么、怎么装、怎么启动。`SKILL.md` 是 Agent 的执行入口，按当前阶段加载 `references/`，再使用 `scripts/` 和 `templates/`。

## 为什么不直接复制参考仓库的目录

参考项目 [xiaolin-explainer-packaging](https://github.com/howoneai/xiaolin-explainer-packaging) 把人读的 README、演示图片放在仓库外层，把完整 Skill 放在同名子目录，并通过 Release 分发 `.skill`。它说明了输入输出、启动确认、真实素材来源和分项许可，适合学习其组织逻辑。

模拟恐怖仓库已有根目录 `SKILL.md`，并已有 GitHub 导入入口。Manus 官方文档明确说明公开仓库根目录可放 `SKILL.md`，因此本次保留这一入口，不用未经验证的目录迁移破坏现有使用方式。[官方说明](https://help.manus.im/en/articles/14753565-how-to-share-and-use-skills-in-manus)。

人读的 README、CHANGELOG 与 `docs/` 不进入 Release 安装包。Agent 包中的入口与相对目录保持原样。

## 安装包的内容

安装包 ZIP 容器根目录应直接出现 `SKILL.md`，以及 `references/`、`scripts/`、`templates/` 和适用的许可文件。不要额外套一个顶层目录，不打入 `.git`、虚拟环境、Node 依赖、浏览器缓存、作者私人反馈、成片工程或账号配置。

第三方许可证应和相应资源放在一起，版权通知不因重新打包而删除。首页中的资源权利说明也应在包内保留，即 `references/资源说明.md`。

Release 附件统一叫 `moni-kongbu.skill`，这样首页的 `releases/latest/download/moni-kongbu.skill` 始终有稳定目标。下载固定版本时，选择对应 tag 的附件。

## 每次更新的逻辑

先读取远端 main 的文件清单，与工作副本比较，避免覆盖别人的改动。只在公开副本上修改，私人安装 Skill 不自动替换。清理姓名、密钥、本机路径、未公开项目记录；原 Skill 的方法和制作能力不因包装更新而随意改变。

随后验证 Skill 元数据、文档相对链接、脚本语法及本次新增功能。打包后检查归档内容，提交经审核的文件，再发布版本和附件。发布后核对远端文件内容与本地副本、附件哈希与包大小，记录本次真实做过的测试。

旧版本保留用于回溯。本次改版不会清除历史提交、历史下载文件或第三方缓存。若需要完全清除历史敏感信息，应另行评估并确认，不能靠改 README 宣称历史消失。

## 版本与测试说明

v1.0.x 记录公开版初始化与作者身份、链接整理。v1.1.0 是发布结构、Manus 启动规则、资源声明和环境检查的增强，不宣称引擎重写或新成片性能提升。

测试应写明范围：Skill 结构、脚本语法、只读环境检查、模板构建、包内容和下载一致性。没有跑完整片时，不能写“完整成片验收通过”；没有在某系统测试时，不能写“所有平台可直接运行”。

不自动上传用户项目，不配置定时同步，不在发布 Skill 时调用图像、视频或语音生成。实际成片创作单独取得对应阶段的确认。

## 发布声明的三个位置

README 开头让新访客立刻知道独立项目、虚构创作及素材边界。`SKILL.md` 要求 Agent 在执行时落实声明。`references/资源说明.md` 保留资源来源与许可例外，让安装包离开 GitHub 后仍携带这些信息。

不能把“公开可读”写成“所有素材免版权”，也不能把“支持导入”写成“点击 GitHub 自动安装”。主页图和演示成片只使用实际完成且可公开的材料，不借别人的图冒充本 Skill 的效果。
